대역 모델은 httpx MockTransport로 외부 응답만 대체했다. 로컬 18051의 실제 HTTP 서버와 Redis 16379·classifier 18010을 사용했다. Docker chaos API는 18050에서 검사했다. 대역 모델 결과를 실제 OpenAI 성공으로 표시하지 않는다.

오류 시험은 연결/HTTP 실패·타임아웃/전체 제한·잘못된 JSON·빈 choices·응답 잘림/거절·미지원 조합·요청 밖 선택·빈 reason·추가 필드·키 미설정·Redis 저장 실패를 포함한다. 모델 오류 시 플래그 저장 0건·요청 1회 이하와 원문 오류 비노출을 검사했다. TDD 초기에는 PUT 즉시 소비 경합 테스트가 실패했고, 레드팀 테스트는 기존 501로 실패한 후 구현으로 통과했다.

주요 명령 (저장소 루트, 격리 QA 환경):

```bash
.venv/qa312/Scripts/python.exe -X utf8 -m pytest src/chaos/tests -q --tb=short
# 위 표의 변경 Python 파일 11개를 각각 경로 인자로 지정
.venv/qa312/Scripts/ruff.exe check --isolated <변경 파일 목록>
uv tool run pyright --pythonpath .venv/qa312/Scripts/python.exe <변경 파일 목록>
docker compose --env-file .venv/qa.env --profile local build chaos
docker compose --env-file .venv/qa.env --profile local up -d redis classifier chaos
.venv/qa312/Scripts/python.exe -X utf8 .venv/stage2_manual.py
```

QA 실행 스크립트·로그·환경은 ignored `.venv/`에 보존했고 값은 문서화하지 않았다. UTF-8 옵션을 빠뜨린 초기 실행은 Windows cp949 계약 파일 디코딩 오류였으며 옵션 적용으로 해결했다. 수동 시험 스크립트의 최초 단언이 기존 계약의 `failure` 필드를 `failure_code`로 잘못 참조하여 수정한 후 재검증했다. FastAPI 핸들러 타입 오류 3개는 함수 타입을 맞춘 뒤 재검사해 해결했다.
