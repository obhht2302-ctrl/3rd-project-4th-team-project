## 직접 관찰

실제 sshd·SSH 키 인증·rsync와 Docker Engine을 사용한 로컬 격리 서버에서 같은 배포 스크립트를 실행했다. 인증 키와 env는 시험용이며 운영 값이 아니다.

- chaos 업로드·서버 빌드·healthy·서비스 식별·성공 메타데이터가 확인됐다. root 및 서비스 `.env`, 다른 서비스 소스, 다른 minwon 컨테이너 10개 ID가 유지됐다. 삭제된 chaos 소스 파일은 대상 폴더에서만 제거됐다.
- 잘못된 known_hosts는 SSH 종료코드 255로 차단됐고 마지막 성공 기록이 유지됐다. 서버 `.env` 누락은 업로드 전 종료코드 1로 차단됐다.
- 실제 서버 flock을 8초 점유한 상태에서 재배포했다. 실행 시간 17.48초, 종료코드 0, 새 성공 메타데이터를 관찰해 서버 잠금 대기를 확인했다.
- 기존 알림 action의 실제 curl 전송 로직을 로컬 HTTP 웹훅으로 실행했다. 성공·실패·취소 메시지 3개가 수신됐다. 실제 디스코드 수신 시험은 아니다.
- GitHub를 읽기 전용으로 조회해 chaos environment, 접속 시크릿 이름 4개, 저장소 알림 시크릿 이름이 존재함을 확인했다. 시크릿 값은 읽거나 출력하지 않았다.

관찰 증거: [JSON 기록](4단계_검증관찰_2026-10-08.json). 시험 후 minwon 11개를 원래 로컬 Compose 설정·중지 상태로 복원했다. 시험 SSH 컨테이너와 전용 네트워크만 제거했으며 기존 볼륨과 다른 프로젝트 컨테이너 3개를 보존했다. 정리 결과는 JSON에 기록했다.

## 남은 인수 조건

실제 GitHub main 실행, EC2 접속·배포, 실제 디스코드 수신, main의 의도적 테스트 실패 시연은 미수행이다. 서버 접속 값은 GitHub environment에서 배포 job이 읽으며 로컬에는 제공되지 않았다. 현재 구현 및 로컬 수동 검증은 완료했지만 계획서의 원격 인수 조건은 완료 처리하지 않는다.

main 반영 후 [실행 절차](chaos_deploy_runbook.md)에 따라 성공 run과 실패 차단 run의 링크·SHA·서버 상태·수신 결과를 추가한다. health는 생존 검사이며 데이터 서버 연결과 전체 업무 처리를 보증하지 않는다. 자동 rollback과 다른 7개 서비스 배포 확장은 포함하지 않았다.
