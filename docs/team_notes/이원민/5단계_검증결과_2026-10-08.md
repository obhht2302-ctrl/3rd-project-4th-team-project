## 수동 QA와 한계

실제 sshd·키 인증·rsync·공통 서버 잠금·Docker Compose를 사용하는 로컬 격리 서버에서 8개 서비스를 순서대로 배포했다. 데이터 의존성과 Mailpit은 먼저 기동한다. Docker daemon을 공유하는 시험 특성상 서버 소스를 전용 시험 볼륨의 실제 경로에 배치해 locator bind mount가 실제 파일을 읽도록 한다. 운영 키·env 값·외부 LLM 호출은 사용하지 않는다.

서비스별 성공 종료·healthy·식별·메타데이터와 다른 컨테이너 10개 ID 보존, root·서비스 env 보존, locator seed 및 frontend→backend proxy를 관찰했다. 시험 후 minwon 11개를 원래 설정·중지 상태로 복원하고 시험 SSH 컨테이너·네트워크·시험 소스 볼륨만 제거했다. 기존 데이터 볼륨과 다른 프로젝트 컨테이너 3개를 유지했다. 최종 관찰 및 정리 결과는 [JSON 증거](5단계_검증관찰_2026-10-08.json)에 기록한다.

GitHub environment 8개 및 각 접속 시크릿 이름 4개의 존재를 읽기 전용으로 확인했다. 값은 읽거나 출력하지 않았다. 현재 main 실행·실제 EC2·실제 디스코드 수신·main 테스트 실패 시연·실제 LLM 업무 흐름은 미검증이다. 각 서비스 로컬 배포가 성공해도 원격 인수 완료로 표시하지 않는다.

[8개 서비스 배포 절차](services_deploy_runbook.md)에 따라 main 반영 후 run 링크·서비스별 실제 서버 SHA·수신 결과·실패 차단 시연을 추가해야 한다. 자동 rollback, DB 마이그레이션, 담당자의 업무 복구 구현은 이번 CI/CD 확장 범위에 포함하지 않았다.

CI 테스트 의존성 검사에서 YAML 2.8.2의 기존 중간 심각도 취약점을 발견해 2.8.3 패치로 고정하고 npm으로 lockfile을 재생성했다. [공급자 2.8.3 수정 내역](https://github.com/eemeli/yaml/releases/tag/v2.8.3)과 [보안 권고](https://github.com/advisories/GHSA-48c2-rrv3-qjmp)에 따른 변경이며 애플리케이션 의존성은 그대로다. 패치 후 workflow 테스트와 audit 결과를 JSON에 기록한다.
