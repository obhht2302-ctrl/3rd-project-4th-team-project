## 발견·수정한 CI 결함

main chaos [실패 run](https://github.com/twlaude/3rd-project-4th-team-project/actions/runs/37797935415)의 pytest는 성공했지만 Ruff I001 5건으로 test job이 실패했다. 배포는 skipped, 실패 알림은 HTTP 전송 성공이었다.

같은 Ruff 0.16.10·같은 소스에서 루트 실행은 통과하고 `src/chaos` 실행은 정확히 5건 실패했다. Ruff의 first-party import 분류가 실행 경로에 따라 달랐다. 테스트 3파일의 import만 CI 기준으로 정렬하고 공통 `scripts/lint_chaos.sh`가 서비스 경로로 이동하도록 했다. workflow가 이 진입점을 사용하고 해당 파일·회귀 테스트 변경을 감지한다. 새 규칙 제외·테스트 삭제·기능 변경은 없다.

재현: 수정 전 `Found 5 errors`; 수정 후 `All checks passed!`, Linux pytest `132 passed`, 진입점 `3 passed`. Linux QA는 Windows read-only bind의 캐시·실행 비트 차이를 피하려고 임시 복사본의 Python 모드를 GitHub checkout의 100644에 맞췄다. 원본 파일 권한·규칙은 변경하지 않았다. 수정의 실제 Actions 재실행은 main 반영 뒤 확인해야 한다.
